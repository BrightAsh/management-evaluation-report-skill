# 실적보고서 작성 (performance-report-writer)

방대한 실적 자료를 읽고, **평가자가 한눈에 이해하는 흐름**으로 엮어 보고서 지면을 만든다. 핵심은 양식을 채우는 것이 아니라 **무엇을, 어떤 순서와 구조로 말할지 설계하는 것**이다. 어느 조직·부서·주제에도 쓴다.

**내용이 먼저다.** 작성 자료가 사실의 근거이고, 성과지표는 방향·필수 목차를, 양식은 표현 구조·말투·지면을 정한다. 자료 분석 → 방향 설정 → 스토리라인 설계를 끝낸 뒤 양식에 배치한다. 양식의 빈칸을 채우려고 약한 내용을 넣거나 흐름을 바꾸지 않는다.

## 도움말 모드

사용자가 작성 자료 없이 이 스킬을 부르거나 "사용법", "도움말", "어떻게 써?"라고 물으면, 작업하지 말고 아래 안내를 그대로 보여준다.

> **실적보고서 작성 도우미**
> 흩어진 실적 자료를 분석해, 평가자가 한눈에 이해하는 흐름의 보고서(PDF·Word)로 만들어 드립니다.
>
> | 구분 | 첨부할 것 | 하는 일 |
> |---|---|---|
> | **필수** | 작성 자료: 결과보고, 계획, 증빙, 회의자료, 과제 목록 엑셀 등 | 내용의 근거 |
> | 선택 | 양식: 따라 하고 싶은 보고서 샘플 | 분석한 내용을 양식의 구조·말투·지면에 맞춰 표현 |
> | 선택 | 성과지표: 편람, 지표 정의서, 평가 기준 | 보고서 방향과 목차를 지표에 맞춤 |
> | 선택 | 가이드라인: 작성요령 | 쪽수·글자 크기 등 규정 준수 |
>
> 지원 형식: PDF, HWP, HWPX, DOCX, XLSX, PPTX, 이미지
>
> **요청 예시**
> - "첨부 자료로 경영평가 실적보고서 2쪽 써줘"
> - "이 양식대로, 첨부한 지표에 맞춰 3쪽으로 써줘"
> - "구성안(스토리라인)만 먼저 보여줘"
> - "○○ 사업을 대표 사례로 강조해줘"
>
> 양식이 없으면 공공기관 실적보고서에서 널리 쓰는 기본 양식(왼쪽 라벨 칸 + 여러 열 표)으로 씁니다. 자료 속 사진·그래프는 꼭 필요한 곳에만 작게 넣고, 전년 대비·목표 대비 같은 비교 값은 메시지를 뒷받침하는 것만 골라 넣습니다.
>
> **받는 것:** PDF·Word 파일, 스토리라인 요약, 자료 사용 내역(넣은 그림·비교 값 포함), 확인이 필요한 사항

## 작업 흐름

각 단계의 세부 방법은 `references/`에 있다. 해당 단계에 들어갈 때 그 문서를 읽는다.

| 단계 | 할 일 | 산출물 | 참고 |
|---|---|---|---|
| 1 | 첨부를 작성 자료 / 양식 / 성과지표 / 가이드라인으로 판별하고 모드(A~D)를 정한다 | 판별표 | `01_inputs.md` |
| 2 | 자료를 **끝까지** 읽고 사실 카드로 뽑는다. 로직모델로 무게를 재고, 사업별 등급(A/B/C)을 매긴다. **비교 값**(전년·전후·목표)과 **그림 후보**(원자료 속 사진·그래프·화면)를 따로 모은다 | `facts.md`, `compare.md`, `visuals.md` | `02_analysis.md` |
| 3 | 방향을 정한다: 지표가 있으면 지표를 해부하고, 없으면 자료에서 도출한다. 핵심 메시지 1문장과 축 2~4개 | `direction.md` | `03_direction.md` |
| 4 | **흐름·구조를 설계한다**: 섹션별 흐름 패턴, 주장형 제목, 문제-성과 짝, 비교 값·그림의 자리, 지면 배분 | `storyline.md` | `04_storyline.md` |
| 5 | 문체·지면을 정한다: 양식이 있으면 문체 프로필을 뽑고, 없으면 **기본 양식** | `style.md` | `05_style.md`, `09_default_template.md` |
| 6 | 블록을 골라 내용 데이터를 쓴다. 그림은 관련 칸 안에 작게 | `content.json` | `06_layout.md` |
| 7 | PDF·Word를 만들고 지면을 맞춘다 | PDF, DOCX | `07_output.md` |
| 8 | 사실·흐름·형식을 점검하고 정해진 형식으로 답한다 | 답변 | `08_quality.md` |

첫 답변에는 판별표와 정한 방향(모드, 핵심 메시지, 축)을 짧게 먼저 보여주고 바로 진행한다. 사용자가 "구성안만 먼저"라고 하면 4단계에서 멈춘다.

## 작업 모드

| 모드 | 첨부 | 방향(무엇을 말할지) | 구조·말투(어떻게 말할지) |
|---|---|---|---|
| A | 자료만 | 자료 분석으로 방향·스토리라인 도출 | 기본 양식 (`09_default_template.md`) |
| B | 자료 + 양식 | 자료 분석으로 방향·스토리라인 도출 | 완성한 스토리라인을 양식의 구조·말투·지면에 맞춰 배치 |
| C | 자료 + 성과지표 | 지표가 방향·필수 목차, 자료 분석이 스토리라인 | 기본 양식 |
| D | 자료 + 양식 + 성과지표 | 지표가 방향·필수 목차, 자료 분석이 스토리라인 | 양식의 구조·말투·지면에 맞춰 배치 |

내용·방향 우선순위: 사용자 지시 > 성과지표 > 작성 자료의 근거와 분석. 형식 우선순위: 사용자 지시 > 가이드라인 > 양식 > 기본 양식. 양식은 사실·방향·스토리라인을 덮어쓰지 않는다.

## 꼭 지킬 원칙

**흐름**
- 결론부터: 문서 → 핵심 메시지 → 축 → 근거. 섹션도 제목(주장)이 먼저 오고 근거가 뒤따른다.
- 제목은 주제가 아니라 주장: '수단 + 으로 + 결과', 가능하면 숫자를 넣는다.
- 제목만 이어 읽어도 핵심 메시지가 전달돼야 한다.
- 문제에서 꺼낸 숫자는 성과에서 같은 단위로 돌아온다. 핵심 성과 수치는 가능한 한 비교 기준(전·후, 전년, 목표)을 붙이고, 적절한 기준이 없으면 출처·기간·범위가 분명한 실수치로 쓴다.
- 모든 대제목은 성과(3줄 이내)로 끝난다. 대표 사례가 앞에 오고, 지면을 더 많이 쓴다.

**사실**
- 원문에 없는 수치·사실은 쓰지 않는다. 모르면 `○○`로 비우고 보고한다.
- 계획은 '추진', 완료는 '달성'으로 구분한다. 목표·추정치에는 표시를 붙인다.
- 수치가 충돌하면 결과보고 > 평가 제출본 > 계획안 순, 같은 단계면 최신 자료를 쓴다.
- 양식은 형식만 빌린다. 양식에 있는 다른 조직의 내용·그림은 절대 섞지 않는다.
- 특정 기관·부서·기술 분야를 미리 가정하지 않는다. 조직명이나 과제명만 보고 AI·디지털·안전 같은 방향을 정하지 말고, 성과지표와 작성 자료의 근거에서 도출한다.

**비교 값**
- 자료에서 같은 지표의 두 시점 값(전년·도입 전·목표)과 전년도 지적사항을 찾는다. 계산은 `scripts/compare.py`로 한다.
- 정의·단위·범위가 같고 두 값 모두 출처가 있으며, 그 섹션의 주장을 뒷받침할 때만 넣는다. 주장 하나에 비교 하나, 섹션당 1~3개.
- 기준값이 작아 %가 부풀려지면 실수치나 배수로 쓴다. 다 넣지 않는다.

**그림**
- 원자료에 있는 사진·그래프·화면만 쓴다. 없으면 넣지 않는다. 새로 그리지 않는다.
- 그 칸의 문장을 직접 뒷받침하고, 작게 줄여도 읽히는 것만. 관련 칸 안에 작게(높이 18~30mm), 쪽당 0~3개.
- 지면이 모자라면 그림부터 뺀다.

**분량**
- 지정 쪽수를 정확히 지킨다. 근거가 충분하면 지면을 채우고, 부족하면 약한 내용을 늘리지 말고 여백을 허용한 뒤 자료 부족을 알린다. 넘치면 등급이 낮은 내용부터 뺀다. 글자 크기로 맞추지 않는다.
- 박스·카드 하나에는 2~3항목만 둔다. 1항목은 1줄(최대 2줄)이다.

## 폴더 안내

```
SKILL.md                 이 파일 (진입점)
references/01~08_*.md    단계별 방법
references/09_*.md       기본 양식 명세(양식이 없을 때)
scripts/read_inputs.py   첨부 일괄 텍스트·그림 추출 + 역할 추정 목록 + 그림 미리보기 모음
scripts/crop_pdf.py      PDF 속 벡터 그래프·표를 그림으로 자르기
scripts/compare.py       비교 값 계산(증감률·%p·배수, 과장 경고)
scripts/render_html.js   content.json → HTML (base.css 사용)
scripts/to_pdf.py        HTML → PDF + 쪽별 채움 측정
scripts/render_docx.js   content.json → Word
scripts/fill_check.py    PDF 쪽별 채움 비율
assets/                  content.json 빈 틀, 작업 기록 서식
examples/demo/           가상 기관 예시 (자료 → 사실 카드·비교 값·그림 후보 → 스토리라인 → 결과)
```

코드를 실행할 수 없는 환경이면 1~6단계를 그대로 하고, 결과는 `07_output.md` 3절의 Markdown 지면안으로 낸다.
