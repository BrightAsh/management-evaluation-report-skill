# 실적보고서 작성 (performance-report-writer-v2-2)

방대한 실적 자료를 읽고, **평가자가 한눈에 이해하는 흐름**으로 엮어 보고서 지면을 만든다. 핵심은 양식을 채우는 것이 아니라 **무엇을, 어떤 순서와 구조로 말할지 설계하는 것**이다. 어느 조직·부서·주제에도 쓴다.

> **이 파일이 `references/`보다 우선한다.** references 일부 문장은 개정 전 기준이다(BEST PRACTICE 상자, 그림 쪽당 0~3개 등). 다르면 이 파일을 따른다 — 맨 아래 'references 보정' 절 참고.

## 도움말 모드

사용자가 작성 자료 없이 이 스킬을 부르거나 "사용법", "도움말", "어떻게 써?"라고 물으면, 작업하지 말고 아래 안내를 그대로 보여준다.

> **실적보고서 작성 도우미**
> 흩어진 실적 자료를 분석해, 평가자가 한눈에 이해하는 흐름의 보고서(PDF·Word)로 만들어 드립니다.
>
> | 구분 | 첨부할 것 | 하는 일 |
> |---|---|---|
> | **필수** | 작성 자료: 결과보고, 계획, 증빙, 회의자료, 과제 목록 엑셀 등 | 내용의 근거 |
> | 선택 | 양식: 따라 하고 싶은 보고서 샘플 | 구조·말투·지면을 그대로 따름 |
> | 선택 | 성과지표: 편람, 지표 정의서, 평가 기준 | 보고서 방향과 목차를 지표에 맞춤 |
> | 선택 | 가이드라인: 작성요령 | 쪽수·글자 크기 등 규정 준수 |
>
> 지원 형식: PDF, HWP, HWPX, DOCX, XLSX, PPTX, 이미지
>
> **요청 예시**
> - "첨부 자료로 경영평가 실적보고서 2쪽 써줘"
> - "이 양식대로, 첨부한 지표에 맞춰 3쪽으로 써줘"
> - "구성안(스토리라인)만 먼저 보여줘"
> - "○○ 사업을 대표 사례로 강조해줘"
>
> 양식이 없으면 기본 양식(제목 → 평가내용 → 핵심성과 → 대제목 순, 왼쪽 라벨 칸 + 여러 열 표)으로 씁니다. 자료 속 사진·그래프·화면은 관련 칸에 적극 넣고(쪽당 2~4개), 자료에 그림은 없지만 있으면 좋은 자리에는 '[이미지 삽입]' 표시 상자를 넣어 드립니다. 전년 대비·목표 대비 같은 비교 값은 메시지를 뒷받침하는 것만 골라 넣습니다.
>
> **받는 것:** PDF·Word 파일, 스토리라인 요약, 자료 사용 내역(넣은 그림·비교 값 포함), 이미지 삽입 표시 목록, 확인이 필요한 사항

## 작업 흐름

각 단계의 세부 방법은 `references/`에 있다. 해당 단계에 들어갈 때 그 문서를 읽되, 이 파일과 다르면 이 파일을 따른다.

| 단계 | 할 일 | 산출물 | 참고 |
|---|---|---|---|
| 1 | 첨부를 작성 자료 / 양식 / 성과지표 / 가이드라인으로 판별하고 모드(A~D)를 정한다 | 판별표 | `01_inputs.md` |
| 2 | 자료를 **끝까지** 읽고 사실 카드로 뽑는다. 로직모델로 무게를 재고, 사업별 등급(A/B/C)을 매긴다. **비교 값**(전년·전후·목표), **그림 후보**(원자료 속 사진·그래프·화면), **그림 자리 후보**(그림은 없지만 있으면 좋은 자리)를 따로 모은다 | `facts.md`, `compare.md`, `visuals.md` | `02_analysis.md` |
| 3 | 방향을 정한다: 지표가 있으면 지표를 해부하고, 없으면 자료에서 도출한다. 핵심 메시지 1문장과 축 2~4개 | `direction.md` | `03_direction.md` |
| 4 | **흐름·구조를 설계한다**: 섹션별 흐름 패턴, 주장형 제목, 문제-성과 짝, 비교 값·그림·이미지 삽입 표시의 자리, 지면 배분 | `storyline.md` | `04_storyline.md` |
| 5 | 문체·지면을 정한다: 양식이 있으면 문체 프로필을 뽑고, 없으면 **기본 양식**(이 파일의 '기본 양식' 절) | `style.md` | `05_style.md`, `09_default_template.md` |
| 6 | 블록을 골라 내용 데이터를 쓴다. 그림·삽입 표시는 관련 칸 안에 | `content.json` | `06_layout.md` |
| 7 | PDF·Word를 만들고 지면을 맞춘다 | PDF, DOCX | `07_output.md` |
| 8 | 사실·흐름·형식을 점검하고 정해진 형식으로 답한다 | 답변 | `08_quality.md` + 이 파일 '점검 추가' |

첫 답변에는 판별표와 정한 방향(모드, 핵심 메시지, 축)을 짧게 먼저 보여주고 바로 진행한다. 사용자가 "구성안만 먼저"라고 하면 4단계에서 멈춘다.

## 작업 모드

| 모드 | 첨부 | 방향(무엇을 말할지) | 구조·말투(어떻게 말할지) |
|---|---|---|---|
| A | 자료만 | 자료 분석으로 스스로 도출 | 기본 양식 (이 파일 '기본 양식' 절) |
| B | 자료 + 양식 | 자료 분석으로 도출 | 양식을 그대로 따름 |
| C | 자료 + 성과지표 | 지표의 세부평가내용이 목차 뼈대 | 기본 양식 |
| D | 자료 + 양식 + 성과지표 | 지표 | 양식 |

우선순위: 사용자 지시 > 가이드라인 > 성과지표(방향) / 양식(형식) > 기본값.

## 꼭 지킬 원칙

**흐름**
- 결론부터: 문서 → 핵심 메시지 → 축 → 근거. 섹션도 제목(주장)이 먼저 오고 근거가 뒤따른다.
- 제목은 주제가 아니라 주장: '수단 + 으로 + 결과', 가능하면 숫자를 넣는다.
- 제목만 이어 읽어도 핵심 메시지가 전달돼야 한다.
- 문제에서 꺼낸 숫자는 성과에서 같은 단위로 돌아온다. 모든 숫자에는 비교 기준(전·후, 전년, 목표)을 붙인다.
- 모든 대제목은 성과(3줄 이내)로 끝난다. 대표 사례가 앞에 오고, 지면을 더 많이 쓴다.

**사실**
- 원문에 없는 수치·사실은 쓰지 않는다. 모르면 `○○`로 비우고 보고한다.
- 계획은 '추진', 완료는 '달성'으로 구분한다. 목표·추정치에는 표시를 붙인다.
- 수치가 충돌하면 결과보고 > 평가 제출본 > 계획안 순, 같은 단계면 최신 자료를 쓴다.
- 양식은 형식만 빌린다. 양식에 있는 다른 조직의 내용·그림은 절대 섞지 않는다.

**비교 값**
- 자료에서 같은 지표의 두 시점 값(전년·도입 전·목표)과 전년도 지적사항을 찾는다. 계산은 `scripts/compare.py`로 한다.
- 정의·단위·범위가 같고 두 값 모두 출처가 있으며, 그 섹션의 주장을 뒷받침할 때만 넣는다. 주장 하나에 비교 하나, 섹션당 1~3개.
- 기준값이 작아 %가 부풀려지면 실수치나 배수로 쓴다. 다 넣지 않는다.

**그림** (기본 양식 원본은 6쪽에 그림 약 23개 — 첫 쪽만 0개, 나머지 쪽 3~8개)
- 원자료 속 사진·그래프·화면을 **적극** 쓴다. 관련 칸이 있는 그림 후보는 모두 배치를 시도하고, 뺀 그림은 사유(조건 불충족·쪽당 상한·지면)를 `visuals.md`에 남긴다.
- 쪽당 **2~4개**(첫 쪽은 0~1개), 최대 5개. 실제 그림과 이미지 삽입 표시를 합쳐 세고, 사진 띠는 1개로 센다. 자료와 자리가 있을 때의 목표이고, 억지로 채우지 않는다.
- 고르는 기준: ① 그 칸이나 그 중제목의 사업·행사·시스템과 직접 관련 ② 줄여도 무엇인지 알아볼 수 있음(글자 빽빽한 슬라이드 통째·표 그림 제외) ③ 우리 조직 작성 자료에서 나온 그림 ④ 로고·아이콘·배경·클립아트 아님 ⑤ 개인정보·보안 정보 없음.
- 관련 칸 안에 넣는다: 칸 아래 높이 20~32mm, 칸 옆 폭 25~35mm, 사진 띠 높이 20~25mm. 한 칸에 그림 1개(사진 띠·카드 제외), 같은 그림은 한 번만.
- 새로 그리지 않는다. 원자료 숫자로 그래프를 만들지 않는다. 양식의 그림은 쓰지 않는다.
- 그림이 없지만 있으면 좋은 자리에는 '[이미지 삽입]' 표시를 둔다(아래 '이미지 삽입 표시' 절).
- 지면이 넘치면: ① 그림 높이 줄이기(최소 18mm) → ② C등급·중복 문장 빼기 → ③ 그래도 넘치면 이미지 삽입 표시 → B·C등급 섹션 그림 순으로 뺀다. 핵심 근거 문장은 그림 때문에 빼지 않는다.

**분량**
- 지정 쪽수를 정확히 지킨다. 빈칸은 자료의 근거로 채우고, 넘치면 등급이 낮은 내용부터 뺀다. 글자 크기로 맞추지 않는다.
- 박스·카드 하나에는 2~3항목만 둔다. 1항목은 1줄(최대 2줄)이다.

## 기본 양식 (양식을 첨부하지 않았을 때 · `09_default_template.md`보다 우선)

기본 양식 원본(경영실적보고서 '평가내용별 추진실적 및 성과' 6쪽)을 실측한 명세다. 렌더러(`scripts/`)의 기본값이 이 지면이다. 원본의 내용·그림은 쓰지 않고 형식만 따른다.

**쪽 틀** (`config.layout`)

| 위치 | 짝수 쪽(왼쪽 면) | 홀수 쪽(오른쪽 면) |
|---|---|---|
| 머리말 | 왼쪽: 장 번호 상자 + 장 제목, 오른쪽 끝까지 가는 선 (`chapter`) | 오른쪽: 회색 띠 안 쪽 머리 제목(평가내용 요약) (`running`) |
| 바닥글 | 왼쪽: 쪽번호 │ 기관명 (`org`) | 오른쪽: 슬로건 │ 쪽번호 (`slogan`) |
| 옆 탭 | 없음 | 오른쪽 가장자리 세로 글(평가내용 요약) (`sidetab`) |

기관명·슬로건은 사용자가 주거나 자료에 있을 때만 넣는다. 로고 그림은 넣지 않는다.

**첫 쪽 — 위에서 아래로 정확히 이 순서**
1. `title` 문서 제목: 'Ⅰ. 20XX년 평가내용별 추진실적 및 성과'(가운데, 큰 굵은 글)
2. `ev` 평가내용 상자: 왼쪽 회색 라벨 '평가내용 1', 오른쪽 평가 항목 원문(1~2줄)
3. `key` 핵심성과 상자: 왼쪽 진회색 라벨 '핵심성과', 오른쪽 '☑ 핵심 메시지 1문장'(굵게, 1줄)
4. 바로 `sec` 대제목 1 → `sub` 가. → 본문 블록

**첫 쪽에 넣지 않는 것:** BEST PRACTICE 상자(`bp`), 대표 사례 요약 상자, KPI 띠(`kpi`), 비전 띠(`vision`), 그 밖의 별도 요약 상자. 핵심성과 다음은 언제나 대제목 1이다. 평가내용이 둘 이상이면 평가내용마다 `ev` + `key` → 대제목들을 반복하고, 같은 규칙을 지킨다.

**대표 사례 표시:** 중제목 끝의 작은 진회색 `B.P` 태그(`sub.tag`) 하나뿐이다. 원본은 6쪽에 2개(대제목 1의 '다.', 대제목 2의 '나.'). 문서 전체 2~3개 이내, 대제목마다 0~1개. B.P 중제목은 대제목 안에서 흐름(체계 → 실행 → 확산)상 자연스러운 자리에 둔다.

**위계·밀도 (원본 실측)**
- 6쪽에 대제목 4개, 대제목당 중제목 3~4개, 쪽당 중제목 2~3개. 대제목은 쪽 중간에서도 시작한다.
- 대제목: 진회색 정사각 번호 상자 + 굵은 주장형 제목 + 오른쪽 끝까지 밑줄. 중제목: '가. 나. 다. 라.' 굵은 글.
- 본문 기본 단위는 라벨 칸 표(`grid`): 왼쪽 회색 라벨 칸 + 열 1~5개. 열 머리는 회색 띠, 칸 첫 줄은 칸 머리(실행 단위·시점, 예: "○○위원회 발족(12월)"), 칸 안 문장 앞 키워드 상자(`[[성과]]` `[[기능]]` `[[내용]]`, 한 칸에 1~2개).
- 추진성과 행(`res: true`)은 진한 라벨 + 연한 띠. 대제목은 추진성과 행 · 향후계획 행 · 기대효과 띠(`res`) 중 하나로 닫는다(원본: 대제목 1=향후 계획, 2=추진성과, 3·4=기대효과).
- 회색 계열만 쓰고, 흰 공간 없이 꽉 찬 지면.

**원본에 나온 지면 → 블록**

| 원본 위치 | 생김새 | 블록 |
|---|---|---|
| 1쪽 1-가 | 환경분석(열 5) → 시사점·비전(한 줄) → 로드맵·목표·전략방향·전략과제(열 3) | `grid` 전략 체계형(`span` 한 줄 칸) |
| 1쪽 아래 | 꺾쇠 구획 제목 한 줄 + 정부과제 선정·내용 표 | `banner` + `grid` |
| 2쪽 1-나 | 역할(열 머리 3) → 추진내용(칸 머리·키워드 상자·**칸 아래 그림 3개**) → 추진성과 | `grid` 역할 비교형 + 칸 `img` |
| 2쪽 1-다 B.P | 열 머리 3 → 현황 및 문제점 → 추진내용 → 추진성과 + 각주 | `grid` 문제 해결형 |
| 3쪽 1-라 | 추진배경 → 개요(구성도 그림) → 주요 참여자(열 4) → 추진실적(**칸마다 사진**) → 향후 계획 | `kv` + `grid` 생태계형 |
| 3쪽 2-가 | 시기 태그 상자 3개 '+' → 진한 결과 띠 | `flow` |

## 이미지 삽입 표시 (자료에 그림이 없을 때)

원자료에 맞는 그림은 없지만 **그림이 있으면 평가자가 더 빨리 이해할 자리**에는 '[이미지 삽입]' 표시 상자를 둔다. 담당자가 나중에 실제 사진·화면으로 바꿔 넣을 자리다. 그림을 새로 그리거나 지어내는 것이 아니다.

**넣을 자리 (우선순위)**
1. 협약·발족·수상·표창·행사 → 행사 사진
2. 시스템·앱·플랫폼 구축·개선 → 화면 캡처
3. 시설·설비·현장 개선, 장비 도입 → 현장 사진
4. 교육·체험·훈련 → 교육 현장 사진
5. 조직 신설·추진체계 구축 → 조직도·구성도 원본
6. 모델·분석 결과 → 결과 그래프 원본(원자료 숫자로 직접 그리지 않고, 원본을 받아 넣도록 표시)

**쓰는 법:** 그림 객체에서 `src`를 빼고 `label`을 쓴다. 렌더러가 PDF에는 빗금 상자, Word에는 회색 상자로 그린다(스크립트 수정 불필요).

```json
{ "h": "○○위원회 발족(12월)", "b": ["…"],
  "img": { "label": "[이미지 삽입] 위원회 발족식 단체 사진", "h_mm": 24, "w_mm": 34 } }
```
- 칸 옆: `"pos": "right", "w_mm": 28`을 더한다.
- 사진 띠: `{ "t": "strip", "h_mm": 22, "items": [ { "label": "[이미지 삽입] 현장 점검 장면" }, { "src": "…" } ] }` — 실제 그림과 섞어도 된다.
- 라벨은 항상 `[이미지 삽입]`으로 시작하고, 뒤에 넣을 것을 15자 안팎으로 구체적으로 쓴다(무엇·어떤 장면).
- 칸 아래 표시는 `w_mm`(30~40)를 꼭 준다. 빼면 칸 폭 전체로 늘어난다.

**분량:** 쪽당 표시 0~2개, 실제 그림과 합쳐 쪽당 5개 이내. 실제 그림을 쓸 수 있는 자리에는 두지 않는다. 표시 때문에 근거 문장을 빼지 않는다. 사용자가 "표시 없이"라고 하면 넣지 않는다.

**코드 없이 쓸 때(Markdown 지면안):** 넣을 자리에 `[이미지 삽입 필요: 무엇 — 위치]`로 적는다.

**답변:** 자료 사용 내역 뒤에 **이미지 삽입 표시 목록**을 표로 준다: `쪽 | 위치(섹션·칸) | 넣을 사진·화면`. Word에서는 회색 상자(표)를 지우고 그 자리에 그림을 넣으면 된다고 한 줄 안내한다.

## 점검 추가 (`08_quality.md` 2절에 더한다)
