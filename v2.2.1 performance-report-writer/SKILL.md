# 실적보고서 작성

작성 자료에서 사실을 선별해 **무엇을 어떤 순서로 말할지** 먼저 설계하고, 그 뒤 양식에 배치한다. 특정 기관·부서·기술 분야를 미리 가정하지 않는다.

## 입력과 우선순위

- **A 작성 자료(필수):** 사실·수치·사례·원자료 그림의 근거
- **B 양식(선택):** 구조·말투·지면
- **C 성과지표(선택):** 방향·필수 평가 항목·배점·지적사항
- **D 가이드라인(선택):** 쪽수·글자 크기·필수 항목·금지 규정

내용·방향은 `사용자 지시 > C > A 분석`, 형식은 `사용자 지시 > D > B > 기본 양식` 순이다. B의 다른 조직·연도 내용·수치·그림은 사용하지 않는다. A가 없으면 작업하지 말고 A의 예(계획·결과보고·증빙·회의자료·과제 목록)를 짧게 안내한다. B/C/D는 선택이라고 알린다.

## 도움말 모드

사용자가 작성 자료 없이 사용법만 물으면 다음만 짧게 안내한다: 작성 자료 A는 필수, 양식 B·성과지표 C·가이드라인 D는 선택이다. PDF·HWP·HWPX·DOCX·XLSX·PPTX·이미지를 받을 수 있고, `자료만 / 자료+양식 / 자료+지표 / 모두` 조합을 지원한다. 결과는 요청한 PDF·Word 또는 구성안과 자료 사용·확인 내역이다. 요청 예시는 `첨부 자료로 경영평가 실적보고서 2쪽 써줘`다.

## 필요한 문서만 읽기

같은 참고문서를 다시 읽지 않는다.

| 조건 | 읽을 문서 |
|---|---|
| A가 있고 구성안·보고서를 작성 | `references/core.md` |
| C가 있음 | 추가로 `references/indicators.md` |
| B가 있음 | 스토리라인 확정 뒤 `references/template.md` |
| B가 없고 PDF·Word·지면안을 만듦 | `references/default_layout.md` |
| 원자료 그림을 검토하거나 `[이미지 삽입]` 자리를 판단 | `references/visuals.md` |
| PDF·Word 또는 `content.json`을 만듦 | `references/layout_render.md` |

도움말·단순 사용법 질문에는 참고문서를 읽지 않는다. 구성안만 요청받으면 B/C는 필요에 따라 읽되, 기본 지면·시각자료·렌더링 문서는 읽지 않는다.

## 작업 흐름

1. 첨부를 A/B/C/D로 판별하고 D의 제약과 요청 분량을 기록한다. 짧은 판별표와 정한 방향을 같은 응답에서 먼저 보여주되, 확인이 꼭 필요한 경우가 아니면 승인을 기다리지 않고 진행한다.
2. **Claude가 이미 분석한 첨부를 다시 텍스트로 추출하지 않는다.** PDF·DOCX·PPTX·XLSX·CSV·TXT·MD·이미지는 첨부 원문을 직접 읽는다. HWP/HWPX처럼 기본 분석이 안 되거나 텍스트가 깨진 파일만 `scripts/read_inputs.py`로 추출한다. DOCX·PPTX·XLSX의 내장 그림만 필요하면 `--embedded-images-only`를 사용한다. 스크립트 소스는 오류 수정 때만 읽는다.
3. `assets/work_ledger.md`를 `work/ledger.md`로 복사해 분석 상태를 한 파일에 유지한다. 원문을 복사하지 않고 사실·판단·출처만 한 번 기록한다. 이후에는 섹션 제목·사실 ID로 필요한 행만 검색하고 원장 전체를 반복해서 읽지 않는다. 별도 `facts.md`, `direction.md`, `storyline.md`, `style.md`, `compare.md`, `visuals.md`를 만들지 않는다.
4. A를 처음부터 끝까지 읽고, 출처가 붙은 사실 → 비교 후보 → 대표 사례 등급 → 공백을 원장에 기록한다.
5. C가 있으면 평가 항목·배점에 맞춰, 없으면 A의 성과와 반복 목적에서 핵심 메시지 1문장과 축 2~4개를 만든다.
6. 주장형 제목과 쪽별 스토리라인을 먼저 확정한다. “구성안만” 요청이면 여기서 결과를 주고 멈춘다.
7. B/D와 지면을 적용해 `content.json`을 만든다. 원자료 그림을 전수 후보화해 쓸 수 있는 만큼 배치하고, 그림은 없지만 실제 사진·화면이 있으면 이해가 좋아질 곳에는 `[이미지 삽입]` 표시를 둔다.
8. `scripts/render_report.py` 한 번으로 요청한 결과물을 만들고 사실·쪽수·시각 품질을 점검한다. 실패한 단계만 수정한다.

사용자가 요구하지 않은 긴 중간 분석문은 출력하지 않는다.

## 절대 지킬 품질 규칙

- 원문에 없는 사실·수치를 만들지 않는다. 모르면 `○○`로 비우고 확인 사항에 적는다.
- 계획·진행·완료, 목표·추정을 구분한다. 계획서에만 있는 일은 완료·달성으로 쓰지 않는다.
- 수치 충돌은 `결과보고 > 평가 제출본 > 중간보고 > 계획안`, 같은 단계는 최신 자료를 우선하고 버린 값도 기록한다.
- 모든 수치·날짜·주장은 원장의 사실 ID와 원문 출처로 되짚을 수 있어야 한다.
- 제목은 주제가 아니라 `수단 + 으로 + 결과`의 주장으로 쓴다. 문제에서 제시한 값은 가능한 한 같은 단위의 성과로 닫는다.
- 비교 값은 정의·단위·범위·집계기간이 같고 두 값 모두 출처가 있을 때만 `scripts/compare.py`로 계산한다. 주장 하나에 대표 비교 하나를 우선하고 섹션당 1~3개만 쓴다.
- 전년도 지적사항은 모두 검토하되 관련성, 올해 조치, 결과 근거가 함께 있는 것만 본문에 넣고 나머지는 사유를 남긴다.
- 근거가 부족하면 약한 내용을 늘려 지면을 채우지 않는다. 중복·저등급 내용을 먼저 뺀다.
- 원자료 그림만 사용한다. 숫자로 새 그래프를 만들거나 B의 그림을 복사하지 않는다. `[이미지 삽입]`은 그림을 생성한 것이 아니라 담당자가 실제 자료로 교체할 자리다.
- 기본 양식에서는 첫 쪽을 `제목 → 평가내용 → 핵심성과 → 대제목 1` 순으로 시작한다. 최상단 BEST PRACTICE 요약을 만들지 않고 대표 사례는 중제목 끝 `B.P` 태그로만 표시한다. B에 다른 구조가 실제로 있으면 B를 따른다.

## 납품

요청한 PDF·Word 또는 Markdown 구성안을 주고, 답변은 다음만 짧게 정리한다.

1. 쪽수·사용한 입력 조합·핵심 메시지
2. 스토리라인: 쪽/섹션 제목/대표 수치
3. 사용·제외한 핵심 자료와 이유
4. 적용한 비교 값·그림의 출처
5. 이미지 삽입 표시 목록: 쪽/위치/필요한 사진·화면
6. 지표·가이드라인 대응(해당 시)
7. 확인이 필요한 충돌·추정·자료 부족

제출 전 사람이 원문과 결과물을 확인해야 하며, 내부 자료는 소속 조직의 보안 규정을 따른다.
